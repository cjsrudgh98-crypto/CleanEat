OVERVIEW프로젝트 개요

식품 뒷면의 성분표는 길고 어렵습니다. 알레르기가 있거나 비건·글루텐프리 같은 식단을 지키는 사람은 제품을 살 때마다 성분을 하나하나 확인해야 합니다. CleanEat은 성분 분석과 쇼핑몰을 하나로 합쳐 “확인하고 → 대안을 찾고 → 바로 사는” 흐름을 한 곳에서 끝냅니다. 결제·취소·반품·재고·매출 통계까지 실제 운영을 전제로 만들었습니다.

PROBLEM SOLVING기술적 도전과 해결

기능을 “동작하게” 만드는 데서 멈추지 않고, 돈이 오가는 흐름과 운영 상황에서 생길 문제를 먼저 찾아 막았습니다.

01결제 금액 위변조 · 중복 결제 방지

문제
클라이언트가 보낸 결제 금액을 그대로 승인하면 금액 조작이 가능하고, 네트워크 재시도·이중 클릭으로 같은 승인/취소가 두 번 나갈 수 있음
해결
승인 전에 서버가 계산한 주문 금액과 대조하고, 토스 API 호출에 멱등 키를 붙임 (부분 취소는 cancel-{주문}-item-{상품}). 주문 행을 비관적 잠금으로 잡아 동시 처리를 직렬화
결과
이미 승인된 결제를 다시 요청하면 토스를 다시 부르지 않고, 이미 취소된 주문·상품의 재취소는 거절 — 테스트로 검증

02가상계좌 웹훅 위조 방지

문제
입금 완료 웹훅은 누구나 호출할 수 있는 공개 URL이라, 위조 요청으로 결제 완료 처리될 위험
해결
발급 때 저장한 secret을 상수 시간 비교로 검증하고, secret이 맞아도 웹훅 본문의 상태는 믿지 않고 토스 API로 다시 조회한 결과만 반영. 웹훅이 오지 않는 환경을 위해 스케줄러가 입금 대기 주문을 주기적으로 확인
결과
위조 웹훅 무시 · 웹훅 유실 시에도 입금 반영

03부분 취소 · 반품의 금액 정합성

문제
상품 단위 취소가 생기면 환불액·재고·주문 상태·매출 통계가 서로 어긋나기 쉬움. 가상계좌 결제는 환불받을 계좌 정보가 추가로 필요
해결
취소한 상품만 환불·재고 복구하고 마지막 상품까지 취소되면 주문 전체를 취소 상태로 전환. 매출 집계는 부분 취소 금액을 빼고 취소·반품 완료 주문을 제외. 가상계좌용 환불 계좌 입력 폼과 검증 추가
결과
관리자 매출 통계가 실제 결제 금액과 일치

04탈취된 토큰 무효화

문제
JWT는 서버에 상태가 없어서, 비밀번호를 바꿔도 이미 발급된 토큰은 만료 전까지 계속 쓸 수 있음
해결
회원별 토큰 버전을 두고 JWT에 ver 클레임으로 넣음. 비밀번호를 바꾸면 버전이 올라가 이전 토큰이 모두 거부됨 (변경한 본인에게는 새 토큰 발급)
결과
비밀번호 변경 즉시 다른 기기의 세션 차단
CleanEat · 포트폴리오6

05스키마 관리: ddl-auto: update → Flyway

문제
Hibernate 자동 스키마 변경은 컬럼 삭제·타입 변경을 반영하지 못하고, 운영 DB에서 어떤 변경이 적용됐는지 추적할 수 없음
해결
H2·MySQL·PostgreSQL 벤더별 마이그레이션(db/migration/{vendor})을 만들고 Hibernate는 validate만 하도록 변경. 이미 운영 중이던 DB는 baseline-on-migrate로 이력만 기록해 이전
결과
마이그레이션을 빠뜨리면 기동 단계에서 바로 실패 · 로컬 MySQL 데이터를 백업 후 무손실로 이전

06N+1 쿼리 제거 · 페이지네이션

문제
상품 목록에서 알레르기·식단 등 연관 데이터를 상품마다 따로 조회해, 상품 47개에 SQL이 143번 실행
해결
default_batch_fetch_size로 연관 엔티티를 묶어 조회. 스캔 기록·주문 내역·관리자 주문 목록은 페이지 단위 응답과 “더 보기”로 변경
결과
상품 목록 쿼리 143회 → 수 회 · 데이터가 늘어도 응답 크기 일정

07OCR 네이티브 의존성과 배포 이미지

문제
tess4j는 시스템 Tesseract/Leptonica 버전에 민감해서 로컬(Windows)에서는 되지만 리눅스 이미지에서 깨질 수 있음
해결
실행 이미지를 Debian trixie로 두고 Temurin 21 JRE만 복사해 넣는 멀티 스테이지 Dockerfile 작성. CI 백엔드 테스트도 같은 배포판 컨테이너에서 실행하고, Dependabot이 OCR을 깨뜨리는 버전을 올리지 않도록 고정
결과
“내 PC에서만 되는 OCR” 방지 · 배포 전 CI에서 확인

08운영 안정성 · 라이선스

문제
메일 서버가 잠깐 안 되면 헬스체크가 DOWN이 되어 배포 플랫폼이 서버를 계속 재시작. PDF 한글 폰트로 재배포가 허용되지 않는 시스템 폰트를 쓰고 있었음
해결
Actuator liveness/readiness를 분리하고 메일 헬스체크는 제외. 메일은 트랜잭션 커밋 후에 발송. 폰트는 나눔고딕(SIL OFL)으로 교체하고 라이선스 전문 포함
결과
부가 기능 장애가 주문·조회를 멈추지 않음 · 저장소/이미지 배포 시 라이선스 문제 없음
